Confirmed findings

HIGH · SH-01 Buy now silently drops selected engraving

Entering Amira, then using Buy now, reaches checkout without Engraving: Amira. The regular Add to cart path preserves it. Source proof: ProductDetailClient.tsx:397–403 calls addItem(rawProduct!, quantity), omitting the engraving / selected variant fields used by :118–129.

Fix: share one cart-line constructor and add an Edge regression that clicks Buy now after selecting engraving.

MEDIUM · SH-02 Mobile sticky bar overlaps personalisation

At 393px, the fixed bottom purchase bar covers part of the engraving module while a shopper reviews a name that cannot be returned. Main CTA remains available, but reviewability is degraded.

Fix: reserve bottom safe-area padding or hide/reposition the bar until configuration has scrolled past.

HIGH · SH-03 Delivery fee is client-controlled at checkout

The server accepts deliveryMethod: delivery plus shipping: 0. The browser math is correct, but a crafted anonymous request can waive delivery. No such order was created.

Fix: calculate delivery/shipping from canonical server-side catalogue subtotal; reject inconsistent payloads.

HIGH · SH-04 Order confirmation email is undeliverable

The guide and failure tests identify the unverified Resend sender domain. A paid shopper may not receive the order number used for tracking.

Fix: verify the sender domain, then run one approved owned end-to-end confirmation test.

MEDIUM · SH-05 Baseline response security headers are absent

Live header capture had no HSTS, CSP/frame protection, nosniff, referrer policy or permissions policy.

Fix: deploy and test a restrictive proxy/application policy, including Stripe flow compatibility.

MEDIUM · SH-06 Cart-recovery endpoint is a branded mail relay

Public cart recovery accepts any recipient address without ownership/consent proof. Per-IP rate limiting limits volume but not recipient abuse.

Fix: use verified browser-bound email or signed recovery token, recipient cooldown and abuse monitoring.

MEDIUM · SH-07 Recovery email promises 50% payment, checkout charges full total

Recovery copy says “Pay only 50% now”; cart/checkout model sets depositNow = total.

Fix: derive mail copy from the checkout policy and test it.

MEDIUM · SH-08 Deploy is hand-built and the Git migration helper cannot authenticate

Coolify serves a hand-built image, not source. The migration helper reads its token but sends literal Authorization: Bearer ***, blocking the remedy.

Fix: correct the variable, dry-run it, then adopt commit-attested Git builds.

LOW · SH-09 White gallery thumbnail appears empty at mobile size

The source image loads but its white-on-white composition is indistinct at 80px.

LOW · SH-10 Guide shows a stale initial count example

The guide says “12 of 41”; current shop initially shows 24 of 41. The functional count itself is correct.
