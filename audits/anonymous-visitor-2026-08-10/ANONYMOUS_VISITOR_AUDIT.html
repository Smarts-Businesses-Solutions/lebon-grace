Confirmed findings

HIGH · F-01Crafted checkout can waive delivery cost

Surface: POST /api/checkout

The server re-resolves catalogue prices but trusts client-supplied shipping and deliveryMethod. A below-threshold delivery basket can submit shipping: 0, resulting in no Stripe shipping line item.

Impact: direct delivery-fee leakage. Fix: derive method and fee exclusively on the server after validating the basket; reject impossible combinations and add forged-payload CI tests. No live Stripe session was created to prove this.

HIGH · F-02Deployed standalone artifact lacks server error instrumentation

The isolated committed build states that .next/server/instrumentation.js is absent and server errors will not reach GlitchTip. The committed hook is at repository root rather than src/instrumentation.ts.

Important distinction: the uncommitted current worktree moves the hook to src/ and its isolated build marker passes. That is not deployed proof. Finish fake-ingest behavioural proof, commit, deploy, and verify an event from production.

HIGH · F-03Order confirmation email sender domain is unverified

USERGUIDES.md records a live Resend 403 for the unverified sender domain; failure-mode tests model the condition.

Impact: a paid customer may receive no confirmation, order ID, review prompt, or follow-up delivery mail. Fix: verify the sender domain and send one controlled real confirmation to a test mailbox.

MEDIUM · F-04Full production E2E gate is red

All three browser projects fail tests/e2e/account/lookup.spec.ts after a 60-second timeout. The test loops twice and uses networkidle, an unreliable readiness condition on a page with analytics activity; failure occurs at the next field fill after the test context closes.

Fix: wait for explicit enabled fields and result state, not network idle. Re-run every project and restore green CI. The unknown-email/wrong-phone indistinguishability assertion should remain.

MEDIUM · F-05Baseline browser security headers are absent

Live root and checkout headers lack HSTS, CSP, frame-ancestors/X-Frame-Options, nosniff, Referrer-Policy, and Permissions-Policy. They expose x-powered-by: Next.js.

Fix: introduce a tested edge/origin policy, then verify Stripe Checkout, analytics, and image optimization still work. This is hardening, not evidence of a current XSS vulnerability.

MEDIUM · F-06Production deployment is not source-driven

Deployment documentation states that Coolify serves a hand-built image and does not clone/build the repository. A green Forgejo build therefore does not prove that the same commit is live.

Fix: complete the git-backed deployment path and attest commit SHA plus image/deployment ID after every release.

LOW · F-07Mobile WhatsApp button overlaps product purchasing copy

At a 393px Edge mobile viewport, the floating WhatsApp control overlaps the price / “Name engraved free” region just above the sticky purchase bar. The main CTA remains visible, but the overlap competes with configuration information.

LOW · F-08Second gallery thumbnail appears empty on mobile

The second ABC Jigsaw Board gallery source image loads correctly, but its very light white-on-white composition is visually indistinct at 80px and resembles an empty thumbnail. Use a higher-contrast crop or thumbnail treatment.

MEDIUM · F-09Public product API leaks non-storefront catalogue data

GET /api/products is allowlisted publicly and returns catalog.getAll() without an admin gate. The stored row shape includes hidden state, stock, supplier/CJ identifiers/prices, arbitrary details, and image-placeholder fields.

Fix: require admin access or return an explicitly public DTO that excludes internal fields and hidden products.

MEDIUM · F-10Cart-recovery endpoint can relay branded email to arbitrary recipients

The public endpoint sends branded mail to a caller-selected address with no proof of recipient ownership, consent, cart ownership, or recipient-level cooldown. Its 3-per-hour/IP cap reduces volume but does not prevent low-volume abuse.

Fix: require a verified, browser-bound cart email or signed recovery token and add recipient-level suppression/abuse telemetry.

MEDIUM · F-11Cart-recovery email promises an obsolete 50% payment model

The recovery message says “Pay only 50% now”; authoritative checkout charges in full. If recovery email becomes deliverable, this is a customer-facing pricing contradiction.

Fix: generate copy from the authoritative checkout payment model and regression-test it.

LOW · F-12Newsletter unsubscribe is not recipient-authorized

The uniform response avoids subscriber enumeration but deletes any supplied syntactically valid email with no recipient-bound token. Someone who knows an address can unsubscribe it.

Fix: use a single-use recipient token in every mailing link.

HIGH · F-13Coolify migration helper uses a literal bearer placeholder

The script reads COOLIFY_API_TOKEN but both API paths send Authorization: Bearer ***, not the token variable. This blocks the very source-driven deployment migration needed to remedy F-06.

Fix: use the variable and test a read-only/dry-run path before any --apply operation.

MEDIUM · F-14Live Stripe test-mode checkout flow is orphaned from CI

tests/e2e/checkout_flow.py is a Python Playwright flow; configured runners discover only the TypeScript suite. It cannot fail CI and may silently rot.

Fix: port it to the configured Playwright suite or give it an explicit controlled Stripe test runner.

MEDIUM · F-15Health installer does not recreate the documented uptime monitor

It promises three timer families but only installs deploy-verification and CI-freshness. A recovery from tracked artifacts misses the two-minute uptime monitor.

Fix: add the uptime service/script/timer and verify an idempotent non-production install.

MEDIUM · F-16Docker build can bypass lockfile reproducibility

The Docker build falls back from npm ci to regenerating/installing a lockfile in-image, while CI does not build the real image. A platform-specific fault can therefore produce a non-reproducible image rather than a red gate.

Fix: remove the fallback from the release path and build the actual image in CI with npm ci only.

Controls that held up

  • Authoritative catalogue pricing is server-resolved.
  • Server validates deliverable email and usable phone.
  • Public mutation routes have endpoint-specific rate limiting.
  • Account lookup requires email + phone and aims not to leak which field is wrong.
  • Reviewed React surface contained no dangerouslySetInnerHTML/raw HTML sink.
  • Checkout return URLs are server-derived; no open redirect found.
  • Mobile layout, tap-target, and rendered accessibility suite passed.

Deliberate non-actions

  • No real payment, Stripe Checkout session, or crafted checkout request against production.
  • No valid contact/newsletter/unsubscribe/cart-recovery email entered.
  • No actual order lookup, review, admin access, or external email.
  • No existing user Chrome tab or user process was closed.
  • Anonymous review cannot prove post-payment/webhook/email/delivery success without approved test credentials.
