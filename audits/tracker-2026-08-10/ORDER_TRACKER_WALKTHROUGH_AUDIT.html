PRODUCTION · EDGE · 2026-08-10

Order Tracker Deep Walkthrough

Accountless, English-only shopper. No real customer credential, order, payment, email or user browser tab touched.

Decision: primary tracker is not reliable until mail works

Anonymous refusal handling, responsive layout, authorization boundaries and status-model tests passed. Unverified sender mail can prevent a customer receiving the order ID needed for this primary flow.

What was proven

  • Non-existent ID + phone produced one ambiguity-preserving error in desktop and 393px Edge.
  • Zero measured horizontal overflow; visual error state is legible.
  • Hit/miss shared ten-per-hour route limit is source-confirmed.
  • All ten statuses have an exhaustive tracker presentation.
  • 24 targeted route/status tests passed.

Confirmed findings

HIGH · TR-01 — Confirmation-email outage can strand tracker

Order ID normally arrives by confirmation mail. The sender domain is unverified; email is refused. Account lookup is a secondary fallback.

Fix: verify sender, then test one approved owned end-to-end lifecycle.

MEDIUM · TR-02 — Lookup throttle resets and does not share state

In-memory rate map resets at deployment/restart and is per replica, weakening the data-lookup protection.

Fix: shared durable/edge rate limit plus operational test.

LOW · TR-03 — No seeded production lifecycle regression

Error/refusal and status unit coverage exist, but safe production has no seeded returned order across all status/courier/terminal states.

Fix: controlled fixture support; never use real customers.
